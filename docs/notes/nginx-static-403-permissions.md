Если статические файлы находятся в домашней директории пользователь www-data, от которого работает воркер процесс, не сможет прочитать файл /home/user1/.../index.html, ему нужен бит `x` на каждом каталоге пути, чтобы проходить через них и обращаться к файлам по имени, и бит `r` для конечного файла, чтобы открыть и прочитать его содержимое. Права на чтение в самих каталогах ему не нужны. 

Команда `namei -l` выведет все компоненты пути и для каждого из них их владельца, группу и биты доступа

Например, посмотрим весь путь до файла index.html:

`namei -l /home/user1/support-lab/nginx/static-site/index.html`

Вывод:
```
drwxr-xr-x root root /
drwxr-xr-x root root home
drwxr-x--- user1 user1 user1
drwxr-xr-x user1 user1 support-labs
drwxr-xr-x user1 user1 nginx
drwxr-xr-x user1 user1 statis-site
drw-rw-r-- user1 user1 index.html
```

Сейчас любой пользователь, который не является владельцем и не входит в группу user1 не сможет пройти через домашнюю директорию пользователя user1.

Это типичный источник ошибки `403 Forbidden` при настройке статических сайтов. 

Если права выдавались через ACL, смотреть их нужно командой `getfacl`.

Способы обеспечить доступ к статике:

- Скопировать файлы в /var/www/static/ `sudo mkdir -p /var/www/static && sudo cp -r nginx/static-site/. /var/www/static`- права на домашний каталог не меняются, но при изменениях файл нужно копировать
- ACL только на проход: `setfacl -m u:www-data:x /home/user1` - требуется поддержка acl файловой системой и те же права на остальные каталоги
- Открыть проход через домашний каталог всем пользователям `chmod o+x`
- Добавить www-data в группу user1, тогда он получает все, что доступно группе user1
`sudo usermod -aG user1 www-data`
